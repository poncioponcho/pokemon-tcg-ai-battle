Detail
B3-1 — broken single-instance lock (deployment-platform bug).
acquire_lock() checks os.path.isdir(f'/proc/{pid}') (line 111). macOS has no /proc filesystem, so this is always False → a second instance never sees the first and overwrites the lock, then proceeds. Since this script is the designated sole submitter (/opt/homebrew/bin/python3 scripts/closed_loop_train.py), two concurrent runs could push two distill kernels or trigger a duplicate submit. Suggest a macOS-safe liveness check (e.g. psutil.pid_exists(pid) or a heartbeat file with mtime).

B3-2 — meta column schema drift (read/write mismatch).
extract.py:392 writes Mt = np.zeros((total_n, 9)) with columns: episode_index, perspective, reward, turn, ctx, n_opts, rank_at_capture, captured_team_index, is_capture_team. train_v2.py:92-94 maps only 7 keys (ep, persp, reward, turn, ctx, nopts, rank_at_capture), so cols 7-8 are never loaded anywhere (AWR weighting only uses meta['reward']). If the captured-team flag was meant to upweight real leaderboard episodes, that signal is currently dead. Confirm intent before fixing.

B3-3 — cardId type sensitivity (needs replay-data check to confirm).
In build_decision, option cardId is indexed as ID2IDX.get(v, 0) where ID2IDX keys are int. If the engine returns cardId as a string (it does for some fields elsewhere in the replay JSON), the lookup misses and writes feature slot 0. I can't confirm the runtime type without a sample replay's option[].cardId; worth a one-line print(type(v)) probe or a try/except/int(v) guard.
