#C1 0 伤害设置招式被完全跳过 — 牌组核心搜牌/加速机制瘫痪
逻辑CSV验证 卡片 764 クレセリア的「みなぎるひかり」(1 能量, 搜 2 超能量贴自身) 和 751 ゼルネアス的「ジオゲート」(1 能量, 搜 3 超系たね上场) 是 0 伤害攻击，但它们是牌组唯一的搜牌/加速手段。代码中 if best_dmg > 0 条件导致这些招式永远不会被选中。
问题代码位置 (line ~418)
# 3. 有攻击选项且 my_active 有能量 → 攻击（选伤害最高的）
if not chosen and attack_idx and my_energy > 0:
    best_idx = attack_idx[0]
    best_dmg = -1
    for k, idx in enumerate(attack_idx):
        ...
        if dmg > best_dmg:
            best_dmg = dmg
            best_idx = idx
    if best_dmg > 0:          ← BUG: 0伤害攻击被跳过
        chosen.append(best_idx)
Replay 证据
subm_rec2 中 card 554 (タブンネ) 仅需 1 能量即可攻击 (attackId=791, 30dmg)，70 个 MAIN 阶段均有 ATTACK 选项。同理，v7 的 764/751 只需 1 超能量即可使用 0 伤害招式。但当前逻辑会跳过这些招式，转而 ATTACH 能量（不能同时攻击）。

卡片招式成本伤害效果
764 クレセリアみなぎるひかり超 (1能)0搜2超能量贴自身

184 ラティアスexむげんのやいば超超● (3能)200下回合不能攻击
修复方案
将 if best_dmg > 0 改为 if best_dmg >= 0，并在无高伤害攻击时优先选择 0 伤害设置招式（搜索/加速）。或者增加判断：当无 2+ 能量的高伤害攻击可用时，优先使用 1 能量的设置招式。
#C2 331 ライジングホーン 对 ex 宝可梦 +100 伤害未计入 — 错过 KO 机会
CSV验证逻辑 CSV 显示 ライジングホーン 伤害为 120，但效果说明为「相手のバトルポケモンが『ポケモン【ex】』なら、100ダメージ追加」。当对手是 ex 宝可梦时实际伤害为 220，但 _CARD_DB 只存了 120。
问题数据 (line ~48)
_CARD_DB = {
    331: {"hp": 210, "moves": [(50, "オーロラビーム"), (120, "ライジングホーン")]},
                                     ↑ 应为 220 vs ex (120+100)
}
影响
KO 检测逻辑 if dmg >= opp_hp 会误判：对手 ex 宝可梦 HP=200 时，实际 220 可 KO 但代码估算 120 不可 KO → 选择发育而非攻击 → 下回合被对手反杀。
修复方案
在 _CARD_DB 中添加条件伤害字段，或在 _estimate_attack_damage 中检查对手是否为 ex：if opp is ex: dmg += 100。判断 ex 可通过 _CARD_DB[opp_cid] 是否存在 "ex" 标记，或在 DB 中添加 "rule": "ex" 字段。
High 严重影响对战性能
#H1 my_energy > 0 检查冗余且有误判风险
逻辑Replay验证 引擎已预过滤合法选项：ATTACK 出现在 options 中即代表能量足够。my_energy > 0 检查是多余的，且当 _get_pokemon_energy_count 解析失败返回 0 时，会错误跳过合法攻击。
问题代码 (line ~409)
if not chosen and attack_idx and my_energy > 0:  ← 移除 my_energy > 0
    ...
Replay 证据
subm_rec2 step 42: active 554 有 1 能量，ATTACK 选项出现且合法。如果 energies 字段解析出错返回 0，Agent 会跳过攻击选择 ATTACH，浪费一回合。
修复方案
改为 if not chosen and attack_idx: — 引擎保证 ATTACK 选项合法。
#H2 184 ラティアスex 特性「スカイライン」未记录 — 撤退费判断错误
CSV验证 CSV 显示 184 有特性 [特性]スカイライン：「このポケモンがいるかぎり、自分の【たね】ポケモン全員の【にげる】ためのエネルギーは、すべてなくなる」。即全场たね宝可梦撤退费→0。但 _CARD_DB 完全没有记录此特性。
影响
牌组全部 4 种ポケモン都是たね（基本），184 上场后所有ポケモン撤退费应为 0。Agent 不知此特性，可能在 HP 危急时不撤退（误以为撤退费太高），或不优先上场 184。
修复方案
在 _CARD_DB[184] 添加 "ability": "skyline"，并在撤退决策中检查场上是否有 184（如有，撤退费=0，应更积极撤退）。
#H3 RETREAT 优先级过高 — 健康 Pokémon 也撤退
Replay验证 Priority 5 在无更好动作时总是选择 RETREAT 而非 END。但撤退会浪费已贴能量，且换上 bench Pokémon 可能更弱。
Replay 证据
subm_rec2 step 8: active 331 (HP=210/210, 1 能量) 仅有 [RETREAT, END] 两个选项。Agent 选了 RETREAT → 撤退到 bench 上可能无能量的ポケモン → 浪费 1 已贴能量 + 暴露更弱ポケモン。
修复方案
Priority 5 增加条件：仅在 my_hp < max_hp * 0.3 或 active 无能量且 bench 有能量ポケモン时才撤退。否则选 END 保留能量。
#H4 _ATTACK_ID_DMG 对 v7 新卡完全为空 — 伤害估算全部依赖 fallback
逻辑 v7 新卡 (184/331/764/751) 的全局 attackId 未知，_ATTACK_ID_DMG 仅包含 v6 旧卡映射。所有伤害估算依赖 option_idx fallback，假设「CSV 招式顺序 = 引擎选项顺序」。此假设仅由 v6 卡 532 验证过，v7 卡未验证。
风险
若顺序不匹配：331 的 オーロラビーム(50) 和 ライジングホーン(120) 可能被反转 → Agent 选低伤害招式而非高伤害 → 严重降低输出。
修复方案
提交后从 replay 反查 v7 卡的 attackId 并补入 _ATTACK_ID_DMG。临时方案：在 _handle_attack 中增加日志（stderr 输出 attackId+card_id），提交后从 agent logs 提取。

#M2 ATTACH 总是贴给 active — 忽略 bench 能量需求
逻辑 _handle_main priority 4 选择第一个 ATTACH 选项，该选项总是 inPlayArea=4（active位）。当 active 已有足够能量时，应转贴 bench ポケモン。
修复方案
在 priority 4 中检查：若 active 能量 ≥ 3（满足全部招式需求），优先选择 inPlayArea=5（bench）的 ATTACH 选项。
#M3 _resolve_card_id_from_option 不处理 area=6
逻辑Replay验证 函数仅处理 area=2(手牌)/5(bench)/4(场上能量)，不处理 area=6。当 context=7 的 CARD 选项含 area=6 时，_resolve_card_id_from_option 返回 -1，导致 HP 排序失效。
修复方案
添加 area=6 分支，查表 players[my_idx] 的 discard 或 prize 列表。或保持默认行为（前 maxCount 个），因为 area=6 选择通常不影响核心战斗。
#M4 ABILITY 优先级最低 — 764/751 的特性被忽略
逻辑 Priority 4 中 ABILITY 排在最后（ATTACH > EVOLVE > PLAY > ABILITY）。但 764/751 的特性/招式是牌组核心搜牌手段，应优先使用。
注意
需区分「特性」(ABILITY, type=10) 和「0伤害攻击」(ATTACK, type=13)。764/751 的 みなぎるひかり/ジオゲート 在 CSV 中是「ワザ」（攻击），在引擎中可能表现为 ATTACK 而非 ABILITY。需 replay 确认。

Deck 设计 牌组构建问题（非代码 bug 但严重影响胜率）
#D1 42 张基本能量严重过多 — 能量洪水
牌组 deck.csv 中 id=5 (基本超能量) 有 42 张，占牌组 70%。标准 PTCG 牌组能量占比 15-25%（8-15 张）。42 张能量导致：
影响分析
指标当前 (42能量)标准 (12能量)
能量占比70%20%
起手无基础概率~10%~5%
每回合抽到能量概率70%20%
手牌能量洪水严重正常
可用地雷区几乎无限需精打细算
修复方案
将能量减至 12-14 张，释放 28-30 个卡位给训练家卡（搜牌/抽牌）和更多ポケモン。
#D2 零训练家卡 — 无搜牌/抽牌/回收手段
牌组 牌组仅含 ポケモン (16张) + 能量 (44张)，无任何训练家卡。PTCG 中训练家卡是核心引擎：
缺失的关键功能
功能训练家卡示例当前替代
抽牌博士の研究, ナンジャモ无
ポケモン搜牌クイックボール, ネストボール仅 751 ジオゲート (1能/回合)
能量搜牌エネルギー転送, ミライトンex仅 764 みなぎるひかり (1能/回合)
回收ふかそうのタネ, スーパーボール无
修复方案
添加 8-12 张训练家卡（如 クイックボール×4, ナンジャモ×2, 博士の研究×2 等），相应减少能量。
#D3 16 张ポケモン偏少 — prize 区耗尽风险
牌组 16 张ポケモン（4 种各 4 张）在 6 prize 比赛中可能不够。若 3-4 只被 KO，剩余ポケモン不足以支撑后期。
修复方案
在减少能量的同时增加 4-8 张ポケモン（可加 1-2 种不同超系基础ポケモ梦），总计 20-24 张ポケモン。

  3. #C2 — ライジングホーン ex 加成：添加对手 ex 检测，+100 伤害。

  5. #H2 — スカイライン特性：添加特性数据，优化撤退决策。
  6. #D1-D2 — 牌组重构：减少能量至 12-14 张，添加训练家卡。预计胜率提升最大。
  7. #H4 — attackId 补全：提交后从 replay 反查，填入 _ATTACK_ID_DMG。
  8. #L1-L3 — 代码清理：低优先级，可批量修复。
