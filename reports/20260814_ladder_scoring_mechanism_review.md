## 一、官方机制原文（WebBridge 实核，evaluation 页）

关键条款逐条摘录（https://www.kaggle.com/competitions/pokemon-tcg-ai-battle/overview → Evaluation）：

1. **Glicko 式评分**：每个 submission 的技能是 N(μ, σ²)，**新提交 μ₀=600 初始化**，σ 随对局数下降。
2. **更新幅度**："magnitude relative to the deviation from the expected result ... and also relative to each Submission's uncertainty σ" —— **σ 越大更新越大，新提交分数波动结构性大于旧提交**。
3. **配对**："try to pick Submissions with similar ratings for fair matches" —— 按相近评分配对。
4. **新提交加速采样**："newer agents playing a much more frequent number of episodes"。
5. **活跃集**："we only track the latest 2 submissions and use those for final submissions"。
6. **榜分展示**："On the leaderboard only your best scoring agent will be shown"（⚠ 与 08-14 02:58 UTC 实证"跟随最新件"存在表述冲突，见 §五 开放问题 Q1）。
7. **终局**：8/16 23:59 UTC 锁定提交后，**继续跑约两周直到榜收敛**，收敛后的 leaderboard 才是最终排名。
8. 单局比分差距不影响评分更新，只有胜/负/平。

## 二、现象成因判定：spike→decay 的主因不是"被刷下去"

### 机制链条（结构性的，任何提交都会经历）

```
μ₀=600（低于池内实际水平）
  → 按"相近评分"配对，早期对手 ≈ 600 分段（池内偏弱一端）
  → 我方真实水平高于此 → 早期 WR 偏高
  → σ 大 → 每局更新幅度大 → μ 快速上冲 = spike
  → μ 升上去后配对到更强对手 → WR 回落 → μ 从峰值向真值回归 = decay
```

**所以 spike→decay 是 μ₀=600 + 相似分配对 + 高 σ 三者叠加的必然轨迹**，不需要"刷分玩家"解释。

### 数据实证（六个自有 ref 的逐局 episodes + 对手当前榜分映射）

| ref | 名称 | 时间分段（前→后）对手均分 | 分段 WR | 前半隐含 μ* → 后半隐含 μ* |
|---|---|---|---|---|
| 55496233 | Router V3 | **570 → 686/628** | 0.67 → 0.44 | **638 → 651（校正后无衰减）** |
| 55496363 | retreat 恢复 | 654 → 644 → **703** | 0.60 → 0.40 | 668 → 640 |
| 55468450 | retreat pivot | 692 → 630 → 748 | 0.50 → 0.56 | 665 → 796 |
| 55499962 | **v22（今天）** | 671 → 731 → **790** | 0.60 → **0.80** | —（仍在上冲段） |

- Router 的 spike→decay 最典型：前 1/3 对手均分仅 570（显著低于池均 ~660–690），原始 WR 从 0.67 跌到 0.44；但按对手强度做 Elo 校正后，**隐含实力 638→651 不降反升**。decay 是配对梯度的测量 artifact。
- retreat 恢复件同构：后段对手均分升到 703，WR 才回落。
- v22 是反例方向：对手强度一路上升（后 5 局均分 790）而 WR 不降，说明它的上冲**不全是弱池假象**。

### 用户假设（"被后来的高分新队刷下去"）的检验

| ref | vs 提交更新的对手 | vs 提交更旧的对手 |
|---|---|---|
| 55451759 configA | **5-13（WR 0.278, n=18）** | 18-17（0.514） |
| 55468450 retreat pivot | 7-6（0.538, n=13） | 19-15（0.559） |
| 55496363 retreat 恢复 | 0-3（n=3，不足） | 14-12（0.538） |
| 55499962 v22 | 0-1（n=1，不足） | 11-4（0.733） |

判定：**该通道存在但不是主因**。只有 configA 一件显示对新队显著劣势（且 configA 本身已判弱）；retreat pivot 对新旧对手无差异。"被刷下去"更多是 §二 的配对梯度 + 池整体随时间变强的正常相对效应。

### 全体合并的强度梯度（ sanity check 通过）

按对手当前榜分五分位：Q1(221–605) 我方 WR=0.829 → Q5(760–1149) WR=0.368，单调递减，说明对手榜分可作为强度代理使用。

## 四、偏度纠正评估方案（建议落地）

现行 tie-break 用原始 WR + 局数 + Wilson 下界，未校正对手强度。建议评估 agent 时改用以下口径（只改评估，不改提交策略）：

1. **主指标改为对手强度校正胜率**：对每个 ref 的 episodes，计算 Elo 期望胜场 `Σ 1/(1+10^((opp_μ − μ)/400))`，用隐含 μ*（使期望胜场=实际胜场的 μ）做跨 ref 比较。本报告的 §二表即用此法，脚本可固化到 `experiments/`。
2. **双条件并列报告**：任何 WR 结论必须同时给出 `对手均分`；两件候选 WR 差 <3pp 但对手均分差 >30 分时，以隐含 μ* 裁决而非原始 WR。
3. **最小置信门槛**：n<20 时只记"方向性"结论（页面不展示 σ，无法从网页读区间宽度；置信门槛只能基于局数与 Wilson 区间，现有纪律已覆盖，继续执行）。
4. **剔除 validation 局**：每个 ref 的第 1 局（self-play validation）不计入（v22 的第 1 局即为 validation，且记为 L，会低估 1 局）。
5. **时点对齐局限声明**：对手分只能取当前榜分，与对局时点存在漂移；跨日比较时把该漂移当 ±20–40 分噪声处理。
