- 一句话方案：基于规则优先级链 + 数据驱动调参的 Mega Lucario ex 卡组与驾驶 agent。

## 1. 卡组构筑（Deck Construction）

### 1.1  archetype 选择与依据
- Mega Lucario ex（678）核心：340HP + Mega Brave 270 斩杀线；Riolu（677）起手率 60.5%（本地采集）。
- Meta 依据：LB 分层 meta 快照（500-699 段 Lucario 占 28.6-35.0% 为第一大卡组）+ 镜像对局丰富 → 选择我们理解最深的 archetype 做深而非追新。

### 1.2 60 卡构成与每张卡的角色（现役 v4 FINAL 为例）
- 宝可梦线：677×4 / 678×4（极简 8 宝可梦，最大化起手与进化链稳定性）
- 能量：斗能 ×13 + 特殊能量（列 ID 与理由）
- 训练家：逐张列角色（检索 1142/1145/1152、过牌 1213、抓人 1088 Prime Catcher? 按实际卡表填、ACE SPEC 1159 Hero's Cape ×1）
- 牌组搜索方法：deck_search 单卡置换爬山（screen n=1000 → confirm n=4000，ckpt 带 n 防污染），联合适应度 mirror+vs_first，3 种子标准闸验收（镜像 ci_lo>0.5、invalid=0、标杆噪声带判读）。

### 1.3 被否掉的方向与证据（体现诚实与迭代）
- 674 Hariyama 破墙打手：v4 搜索收敛移除（-674+1152）
- 1235 Waitress 入组：3 种子配对闸证伪/噪声带内（ledger#86）
- F2c 延迟进化蓄能：实测 vf -2.05pp 回归 → 回滚（ledger#91）

## 2. Agent 设计（Solution Originality）

### 2.1 决策架构
- 优先级链（P1 KO 攻击 → P2 铺场 → P3 核心进化 → … → 收尾），关键分支举例（ex 免疫墙识别、Boss's Orders 防范、奖赏冲刺阈值）。
- 引擎对齐原则：所有规则以模拟器实测行为为准（官方帖 708586 差异清单），不套用正版规则。

### 2.2 数据驱动调参
- param_tune 参数山爬 + vs_first 回归门禁 + self-test 探针；
- vsfirst 诊断采集器（决策类型频次 / Mega 上场回合与能量 / 死亡时刻 bench 快照）→ F1/F2a 等修复的证据链。

### 2.3 评估方法学（原创性重点）
- ±1.7pp 噪声铁律（PYTHONHASHSEED/跨进程熵的量化与对策）；
- 3 种子标准闸 + 标杆对标 + STRONG/MARGINAL/REGRESS 分类；
- 「瞬读不记账」：rating 从 600 起评、~22-24h 收敛的机制认知与结算复核流程。

### 2.4 探索过的其他范式与取舍（NN/RL 负结果的含金量）
- 蒸馏 student（保真天花板 0.75-0.80、nn_first 0.40 未破阈）→ 关闭；
- bcrl RL（0.5223 < 0.5379 阈值）→ 关闭；
- 搜索 oracle（1-ply/beam）→ deferred，外部对标（#9 选手 Lucario ~1005 用 beam search + 对手原型贝叶斯检测 + IS-MCTS）证明该方向可行，列为后续路线。
