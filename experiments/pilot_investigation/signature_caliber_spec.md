## §1 签名定义 + 选义理由

### 轴 R —— 自愿换位轴（retreat / voluntary switch）

| 编号 | 指标 | 定义（冻结口径） |
|---|---|---|
| R1 | `sw8_vol_pg` | 每局 **type8 自愿换位**次数（active↔bench swap，剔除 Boss gust 受害配对；含付费 retreat + 卡驱动换位，**不可再细分**） |
| R2 | `sw8_postko_vol_pg` | = R1 − `sw8_vol_pre_pg`，即**首次 KO/丢奖之后**的自愿换位/局（reactive prize-protection 载体） |
| R3 | `sw8_atk%` | `sw8_atk / sw8_vol`：自愿换位换上来的怪**当回合即攻击**的比例（换位质量） |

**选义理由**：
- replay 日志里 5→4（bench→active）移动**几乎全是 KO 后强制升场**（`sw_postko`），自愿分量 ≈ 0（各组 `sw_vol_pg` 实测 0.0–0.19）——所以 5→4 不是决策载体，**真决策载体是 type8 swap**。早前 4→5 代理口径不存在于数据中（retreat 仪器一度全表 0.0 = 盲维），已废。
- 8/12 19:53 刀已定位：换位总量双方无差（setup 期 `sw8_vol_pre` 双方 0.4–1.3 重叠），**差距全在首 KO 后的 reactive 段** → 对齐目标只钉 R2；R1 作总量监控防旋钮过冲，R3 实测无系统差（见 §2）只监控不设目标。
- type8 自愿子集**不含付费/卡驱动细分**（冻结解析器无此字段）——这是口径的一部分，不是缺陷；想要细分必须两侧同步扩展（见 §4 扩展条款）。

### 轴 E —— 能量灌注轴（energy attachment）

| 编号 | 指标 | 定义（冻结口径） |
|---|---|---|
| E1 | `pre_act%` | **首次 KO/丢奖之前**，type11 能量挂载落在 **active** 的比例；分母 = 全部 pre-KO type11 事件（**含 serial 未定位事件**，约占 65–70%，两侧同此约定故可比） |
| E2 | `pre_bench%` | 同上，落 **bench** 的比例（E1 的镜像监控项） |
| E3 | `nrg_act%` | **全局**（含 post-KO）type11 落 active 比例；分母 = 全部 type11 |

**选义理由**：
- pre-first-KO 防伪刀（8/12 18:49）已证「症状说」不成立：任一方都还没丢奖时差距就存在（我们赢局 28.2% vs Sixth/ミワ 赢局 6–11%）——是开局策略差不是输局被迫 → 对齐目标钉 **E1（pre 窗口）**；E3 全局值只监控。
- 能量目标定位靠 serial→area 追踪器（type6/7 事件维护），未定位事件**计入分母、不计入分子**——两侧必须同此分母约定，否则比例不可比。
- **Dipam 双组 E1 ≈ 30%（W 30.0 / L 30.8）= deck 混杂样本**：他的牌组天生 active-heavy，W/L 无差。目标带只用 **Sixth + ミワ 干净样本**；Dipam 单列作对照，**不并入目标带**。

### Boss 轴 —— 只监控，无对齐目标

`boss_pg`（Boss's Orders = type4 且 cardId==1182 的打出/局）。8/12 已判无 portable 差：
bos676（猎 Solrock 引擎）是我们牌组特有的被针对面，真人对手池不跑 Solrock（各组 `boss_676%` = 0）；
且我们自己 Boss 用得反而更多（3.09–3.84 vs 真人 1.65–3.18）。**不设对齐目标，仅防退化监控。**
（1142 = Fighting Gong，**不是** Boss；别再混。）

## §3 量测方法（精确抽取步骤）

### 3.1 replay 侧（目标值侧，= `top_pilot_analyze.py` 冻结实现）

逐事件口径（8 条， parity 声明的对象）：

1. **新鲜窗口**：逐 step 取 `observation.logs`，与上一 step 完全相同则整步跳过（`lg != prev_lg`）。
2. **单侧视角**：事件按 `playerIndex` 分侧；聚合时按该局 `seat` 取被测 player 侧（seat=1 的局取反会翻转，禁止直接平均两侧）。
3. **换位**：`type==8` = active↔bench swap。若对手侧有未配对的 Boss 打出（pending_boss）→ 记 `sw8_gust`（受害，非决策）并配对消耗；否则记 `sw8_vol`（自愿决策），并记录换上来的 `cardIdBench` 待配对下一次攻击（该怪下一次 type15 攻击命中 → `sw8_atk`）。5→4 移动（type6/7, fromArea=5→toArea=4）只作 `switch/postko/gust` 分解，**不进** R 轴。
4. **能量**：`type==11` 记一次挂载；用 serial→area 追踪器（type6/7 事件的 `(side, serial) → toArea` 映射）查 `serialTarget` 落点：area 4 = active、5 = bench、查不到 = 未定位（计入分母）。
5. **首 KO/丢奖界**：事件序号单调递增（新鲜窗口内）；第一个满足 `toArea==3 且 fromArea∈(4,5)`（KO）或 `fromArea==6 且 toArea==2`（拿奖）的事件序号为界；界前事件进 pre 窗口。
6. **Boss**：`type==4 且 cardId==1182` 记 `boss` 并置 pending_boss。
7. **KO 受害者**：`toArea==3 且 fromArea∈(4,5)` 的 cardId 与奖品值记在**攻击方**账上（mapping 偏好）。
8. **镜像局**：`TeamNames` 双同名 → flag，不进任何分组（#132 教训）。

### 3.2 obs 侧（N1 本地量测，advisor 双实例 harness，读对手侧决策）

要求映射到与 §3.1 **同一事件语义**，禁止「等价简化」：

- 换位/retreat 决策 = select 选项中 active↔bench swap 动作（8/12 词汇反推的 `(6,5,4)` 选项元组口径）；**必须剔除** Boss gust 受害换位（对手打 1182 后的被动换位），只统计自愿决策。
- 能量挂载决策 = attach energy 动作的目标怪位置（active/bench）；obs 侧可直接读目标，无 serial 未定位问题——**但聚合分母必须与 §3.1 可比**：若 obs 侧全量可定位，需在报告里并记「replay 口径折算值」（乘以历史定位率 ~30–35%）或直接改用全量口径并重导真人目标值（见 §4 扩展条款）。**二选一，不许静默混用。**
- pre 窗口界 = 本局首次 KO/丢奖发生的决策点之前，同 §3.1-5。

## §4 口径 parity 声明

1. N1（及后续 N2/N3）一切签名量测**逐字复用** §3.1 的 8 条口径与 §2 的冻结目标值；任何「等价简化」（如不剔 gust 受害直接数换位、分母只计已定位事件、pre 界改用回合数近似）都视为**口径漂移**，产物作废。
2. **扩展条款**：新增细分（如付费 retreat vs 卡驱动换位）必须两侧原子同步——扩展解析器重导 68 局真人目标值 **且** obs 侧同步实现，同一次提交落地；否则不做。
3. 本 spec 的修订只能以「新 spec 版本 + ledger 记录 + cheat sheet 引用更新」三件套落地，禁止口头改口径。
